EL PRODUCTO

Las lámparas de acuario que encontraba no se podían ajustar a mi gusto. Yo quería mover cada color por separado, programar un día entero con su amanecer y su atardecer, y controlarlo desde el móvil sin depender de la app de un fabricante. Así que la hice yo: la diseñé en 3D, repartí los LEDs en cinco canales, monté los drivers y el ESP32, y escribí el firmware y la app. Está montada y funcionando sobre el acuario.

INFRAESTRUCTURA TÉCNICA

  • PLACA: ESP32 con cinco salidas PWM de 10 bits a 1 kHz, una por driver de LED.
  • FIRMWARE: C++ con el entorno de Arduino; versión 4.1.
  • APP: HTML, CSS y JavaScript guardados en la memoria del ESP32 y servidos por HTTP.
  • SENSORES: sonda de temperatura digital (bus OneWire) y ventilador regulado por PWM.
  • DISEÑO: modelo 3D completo en SketchUp y esquema de cableado propio.

02 / LA APP

La sirve la propia lámpara

No hay nada que descargar. El ESP32 lleva dentro un servidor web con la app: se abre en el navegador del móvil y se puede añadir a la pantalla de inicio, donde se abre a pantalla completa como una app más.

  • Manual o automático: en manual, un deslizador por canal; en automático, la lámpara sigue el día programado con la hora de internet (NTP).
  • 12 perfiles: cada uno con nombre propio y hasta 24 puntos de hora y brillo por canal. Entre punto y punto, la luz cambia poco a poco.
  • Vista previa: al editar un perfil, mueves la hora y ves en la lámpara real cómo quedaría la luz.
  • Efecto nubes: cada 4 a 12 segundos el brillo baja al azar hasta un 15 % y vuelve despacio.

04 / PROTECCIÓN TÉRMICA

El calor manda sobre el diseño

Los LEDs de potencia se calientan, y el calor les acorta la vida. La sonda mide la temperatura cada dos segundos y la lámpara reacciona sola. La app muestra la temperatura y la velocidad del ventilador, y deja ajustar todos los límites.

  • Ventilador con histéresis: arranca a 28 °C, no se apaga hasta bajar a 26 °C y llega al 100 % a 38 °C. Así no se enciende y apaga sin parar.
  • Potencia mínima: cuando gira, nunca baja del 30 %, porque por debajo zumbaba sin moverse.
  • Límite de brillo: a partir de 45 °C el brillo máximo baja al 50 % poco a poco, y se recupera al bajar de 40 °C.

07 / EN EL CÓDIGO

Fragmentos reales del firmware

Brillo a cualquier hora

Cada canal guarda puntos de hora y brillo. Esta función busca entre qué dos puntos está la hora actual e interpola. Si el tramo cruza la medianoche (por ejemplo, de 22:00 a 07:00), suma 24 horas para que la cuenta salga bien.

La usan tanto el modo automático, con la hora de NTP, como la vista previa, con la hora que eliges en la app.

Lampara-Led.ino · getTargetFromSchedule()C++
int currentMinutes = h * 60 + m;
// … busca p1 (último punto antes de ahora) y p2 (el siguiente)

// Ajuste para el ciclo de 24h
if (m2 < m1) m2 += 1440;
int adjustedCurrent = currentMinutes;
if (adjustedCurrent < m1) adjustedCurrent += 1440;

float diff = m2 - m1;
float pos = (float)(adjustedCurrent - m1) / diff;

int briPercent = pt1.bri + (int)(pos * (pt2.bri - pt1.bri));

if (briPercent <= 0) return 0;
return map(briPercent, 1, 100, 30, PWM_MAX);
Del brillo al pin

En cada vuelta del bucle, el valor de cada canal pasa por las nubes, el límite térmico y la corrección gamma antes de llegar al pin. El límite (safetyMultiplier) se mueve poco a poco, así que nunca hay un apagón brusco.

La salida va invertida porque los drivers apagan la luz con la señal alta.

Lampara-Led.ino · loop()C++
// Aplicar el límite máximo de seguridad (Hard Cap)
int maxAllowed = (int)((float)PWM_MAX * safetyMultiplier);
int limitedValue = (finalValue > maxAllowed) ? maxAllowed : finalValue;

double input = (double)limitedValue / (double)PWM_MAX;
double output = pow(input, 1.5);
int valorGamma = (int)(output * PWM_MAX);
if (limitedValue == 0) valorGamma = 0;

int pwmFinal = PWM_MAX - valorGamma;
// … recorta pwmFinal entre 0 y PWM_MAX
ledcWrite(channels[i].pin, pwmFinal);
